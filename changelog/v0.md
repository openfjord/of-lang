# Changelog — version 0.x

All notable changes for major version 0.

---

## [0.2.0] - unreleased

### Added

- **language**: `Doc`, a definition that names a Markdown file in `docs/`, and a `docs` key on kinds that lists the docs that tell more about the kind. Each file in `docs/` must have a `Doc`, unless a different doc refers to it
- **language**: `format: uri` for text fields: an absolute URI (Uniform Resource Identifier), such as `https://recipes.example.com/pesto`
- **of-lang**: Checks `Doc` definitions, the `docs` of kinds, and that each file in `docs/` has a `Doc` or a doc that refers to it
- **of-lang**: Checks values against `format: uri`
- **examples**: Tags: `allergens` marks what an allergen app needs, and `spoilage` marks a new model of batches, storage zones and their temperatures, which only the kitchen uses and the package does not export
- **examples**: An `AllergenSafety` doc, which the `Allergen` kind lists
- **examples**: A `URL` value type, and a required `steps` field on `Recipe` with the address of the recipe's steps
- **examples**: A second package, `@bistro/suppliers`, which the restaurant depends on and imports from in `defs/buying.of.yaml`; the restaurant's manifest now has `dependsOn` and `openFor`
- **docs**: The language by example, in `docs/by-example/`: short pages that each show one thing, with the text next to the code. Each page has a small package of its own, and a script checks that the page shows that package exactly and that `of-lang check` and `of-lang test` pass on it. The first two pages are `hello-kind` and `defaults`

### Changed

- **language**: Two names in a package must differ by more than case, so `BaseRecipe` and `baseRecipe` cannot both be names (FL6); the name of a statement in a test file must also differ from each definition by more than case (FL8)
- **of-lang**: Reports names that differ only by case
- **examples**: The derivative `baseRecipe` is now `baseRecipeFromUses`, because the kind `BaseRecipe` has the same name in a different case
- **language**: Every YAML snippet in the reference is a file of the restaurant example, or a part of one, named in its first line. Statements that the restaurant has are shown exactly as they are, and a script checks each snippet with `of-lang check` and `of-lang test`

## [0.1.0] - 2026-11-17

### Added

- **language**: The draft specification: an overview of why ontologies are hard for software people, a cheat sheet, and a reference for kinds, links, facts, derivatives, constraints, tags, packages, files, tests and pending changes
- **of-lang**: A command-line tool with `check`, `run`, `explain`, `diff`, `test` and `version` commands, and text or JSON output. It implements the draft: each problem it reports names the rule it breaks, and it checks a package with a pending change both with and without the change
- **examples**: `examples/restaurant/`, a package about a restaurant's kitchen stations, recipes, dishes, ingredients and allergens
- **install**: The tool installs with Homebrew from the `openfjord/tap` tap, with `go install`, or as a prebuilt binary from the GitHub release
