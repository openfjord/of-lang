# Changelog — version 0.x

All notable changes for major version 0.

---

## [0.3.0] - unreleased

### Changed

- **docs**: The site has a home page of its own, `docs/home.md`, which tells what the language is, what a model is good for and what it is not, and shows one small example with the answer of the tool and its reason. The README is shorter, for readers on GitHub, and is not a page of the site
- **examples**: `examples/quickstart` holds one package, `depends-on`, which the README and the home page show

## [0.2.0] - 2026-11-19

### Added

- **language**: `Doc`, a definition that names a Markdown file in `docs/`, and a `docs` key on kinds that lists the docs that tell more about the kind. Each file in `docs/` must have a `Doc`, unless a different doc refers to it
- **language**: `format: uri` for text fields: an absolute URI (Uniform Resource Identifier), such as `https://recipes.example.com/pesto`
- **of-lang**: Checks `Doc` definitions, the `docs` of kinds, and that each file in `docs/` has a `Doc` or a doc that refers to it
- **of-lang**: Checks values against `format: uri`
- **examples**: Tags: `allergens` marks what an allergen app needs, and `spoilage` marks a new model of batches, storage zones and their temperatures, which only the kitchen uses and the package does not export
- **examples**: An `AllergenSafety` doc, which the `Allergen` kind lists
- **examples**: A `URL` value type, and a required `steps` field on `Recipe` with the address of the recipe's steps
- **examples**: A second package, `@bistro/suppliers`, which the restaurant depends on and imports from in `defs/buying.of.yaml`; the restaurant's manifest now has `dependsOn` and `openFor`
- **docs**: The README shows three small examples about services and teams, and each one is complete: the tool catches a wrong value, concludes which service depends on the database, and rejects a service that has no owner. The text that tells which problems a model solves is in `docs/why.md`
- **docs**: A diagram on the README and the home page of the site: knowledge and facts go into the language, which produces a model, and the model is used to generate code, to give knowledge to an agent, and as the base of a semantic layer and of a knowledge base
- **examples**: Three small packages in `examples/quickstart`, which are the examples that the README shows
- **docs**: The language by example, in `docs/by-example/`: short pages that each show one thing, with the text next to the code. Each page has a small package of its own, and a script checks that the page shows that package exactly and that `of-lang check` and `of-lang test` pass on it.
- **docs**: An introduction to the language, in `docs/introduction/`: eight chapters that grow the restaurant package one result at a time. Each chapter is a question of the kitchen, such as "Does the margherita contain nuts?", and ends with the answer of the tool. `docs/introduction/steps/` holds the package as it is after each chapter, and the last one is the same as `examples/restaurant`. A script checks that each chapter shows its package exactly and that `of-lang check` and `of-lang test` pass on each package
- **examples**: A second full example, `@acme/platform` in `examples/platform`, about the services, tables, data classes, backups and regions of a software product. It depends on `@acme/org` in `examples/org`, which has the teams. The reference, the by-example pages and the page of the tool use this example, and the introduction keeps the restaurant
- **docs**: A documentation site with every page of the repository that has a title, a navigation, and a dark and a light theme. `scripts/build_site.py` builds it, and fails on a link to a file or a heading that does not exist

### Changed

- **language**: A file must not import a name that it does not use (FL20)
- **of-lang**: Reports each name that a file imports and does not use
- **examples**: The test file `batch-kept-too-warm.of.yaml` does not import `useByAfterArrival`, because it does not use it
- **language**: Two names in a package must differ by more than case, so `BaseRecipe` and `baseRecipe` cannot both be names (FL6); the name of a statement in a test file must also differ from each definition by more than case (FL8)
- **of-lang**: Reports names that differ only by case
- **examples**: The derivative `baseRecipe` is now `baseRecipeFromUses`, because the kind `BaseRecipe` has the same name in a different case
- **language**: Every YAML snippet in the reference is a file of the platform example, or a part of one, named in its first line. Statements that the platform example has are shown exactly as they are, and a script checks each snippet with `of-lang check` and `of-lang test`

### Fixed

- **of-lang**: A condition on a part of a `oneOf` field allows the value of each choice that defines the part, not only of the first choice

## [0.1.0] - 2026-11-17

### Added

- **language**: The draft specification: an overview of why ontologies are hard for software people, a cheat sheet, and a reference for kinds, links, facts, derivatives, constraints, tags, packages, files, tests and pending changes
- **of-lang**: A command-line tool with `check`, `run`, `explain`, `diff`, `test` and `version` commands, and text or JSON output. It implements the draft: each problem it reports names the rule it breaks, and it checks a package with a pending change both with and without the change
- **examples**: `examples/restaurant/`, a package about a restaurant's kitchen stations, recipes, dishes, ingredients and allergens
- **install**: The tool installs with Homebrew from the `openfjord/tap` tap, with `go install`, or as a prebuilt binary from the GitHub release
